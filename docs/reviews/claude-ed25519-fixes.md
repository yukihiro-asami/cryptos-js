## 原因と修正

1. **署名値の最終還元**：`sc25519MulAdd`が返す値がℓ以上になる場合があった。32バイトのゼロseedとメッセージ`0c230000`では、正しいsよりℓだけ大きい署名となり、自身とNode.jsの双方が拒否した。最後に必要な場合だけℓを1回引く。非負の256ビット入力なら`x=ab+c < 2^512`であり、`floor(2^520/ℓ)`を使う商の推定誤差は高々1。この補正で`0 ≤ s < ℓ`を満たす。
2. **射影座標から拡張座標への変換**：XYZをコピーしてT=XYとすると、Z≠1で`XY=ZT`を保てない。`(XZ,YZ,Z²,XY)`へ変換し、同じ点と拡張座標の関係を保つ。Tを先、Zを最後に計算し、同じオブジェクトへの変換にも対応する。位数8の成分を含む検証ケースが正しく通ることも確認した。

署名形式・公開API・余因子付き検証の方針は変更しない。別のレビュー指摘、解説の再構成、公開・コミットは対象外。

## 回帰試験

[追加試験](../../tests/ed25519-arithmetic.test.mjs)を`npm test`へ組み込む。修正前の実装で5群中4群が失敗し、改変を拒否する1群が成功した（[修正前ログ](claude-ed25519-fixes/regression-before.tap)）。

- 乗加算180組：ℓの倍数の前後、署名入力と256ビット最大値を、JavaScriptの剰余演算による期待値と比較する。
- ゼロseed／`0c230000`の署名：Node.jsと全64バイトの一致、sの範囲、双方での検証を確認する。
- 座標変換40組：基点・その負点・単位元・位数2の点、5種類のZ、別オブジェクト／同一オブジェクトで、元の点と`XY=ZT`を確認する。
- 独立したアフィン座標計算で、差の位数が1・2・4・8の検証ケースを生成し、8倍した検証式の成立と実装の受理を確認する。Node.jsの厳しい受理規則を、これらのケースの期待値にはしない。
- 4ケースそれぞれについてs・メッセージの改変、位数8の公開鍵／Rを拒否する。

既存試験2件も修正する。乗加算後の再還元を除いて不具合を隠さないようにし、座標変換では誤った固定値の期待を、実際の曲線上の点と不変条件の検査へ置き換える。
